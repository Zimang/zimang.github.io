# [C#中的协变与逆变：数组协变性](https://learn.microsoft.com/zh-cn/archive/blogs/ericlippert/covariance-and-contravariance-in-c-part-two-array-covariance)



C# 通过两种方式实现变体。今天要讲的是有缺陷的那种。

自 C# 1.0 起，元素类型为引用类型的数组就是协变的。下面这段代码完全合法：

```c#
Animal[] animals = new Giraffe[10];
```

由于 Giraffe 比 Animal 小，而“创建数组”是一个对类型的协变操作，所以 Giraffe[] 比 Animal[] 小，因此其实例可以放入该变量中。

不幸的是，这种特定的协变是有缺陷的。它被添加到 CLR 是因为 Java 需要它，而 CLR 设计者希望能够支持类 Java 语言。我们随后又将其添加到 C# 中，因为它已在 CLR 中。这个决定在当时颇具争议，我也对此不太满意，但现在我们已经无能为力了。

为什么说它有缺陷呢？因为将 Turtle 放入 Animal 数组通常应该是合法的。在语言和运行时中启用数组协变后，你无法保证 Animal 数组能够接受 Turtle，因为其底层存储可能实际上是一个 Giraffe 数组。

这意味着，我们将一个原本可以由编译器捕获的错误，变成了一个只能在运行时捕获的错误。这也意味着，每次向数组放入对象时，我们都必须进行运行时检查以确保类型匹配，否则就抛出异常。如果你要向数组中放入海量数据，这可能会带来巨大的开销。

唉。

不幸的是，我们现在只能接受这个现实。Giraffe[] 比 Animal[] 小，事实就是如此。

我想借此机会澄清一下在**第一部分**评论中提出的一些观点。

首先，我所说的“子类型”和“超类型”，对于类是指“在基类链上”，对于接口是指“在基接口树上”。我并非指更广泛的“可替代”概念。而对于“比…大”和“比…小”，我明确指**不是**“是…的超类型”和“是…的子类型”。确实，每个子类都比其超类小，但反之则不成立。也就是说，并非每个更小的类型都是其更大类型的子类型。Giraffe[] 比 Animal[] 和 System.Array 都小。显然 Giraffe[] 是 System.Array 的子类型，但它**绝对不是** Animal[] 的子类型。因此，我定义的“比…小”关系比“是一种”关系更普遍。我想区分赋值兼容性（比…小）和继承（是…的子类型）。

下次我们将讨论在 C# 2.0 中添加的一种没有缺陷的变体。

  - 问得好。在这种情况下，协变是完全安全的，因为你在此方法中将数组视为只读的。只有当你试图向数组写入时才会出现潜在问题，而你这里并没有这样做。获得安全协变的方法是将只读操作分离到接口中并使它们协变。如果你编写的程序接受两个 `IEnumerable<object>` 对象，并且我们能够以某种方式使 `IEnumerable<T>` 在 T 上协变，那么这将完全是类型安全的。IEnumerable 不允许你写入对象，只能从中读取，因此它对于协变是安全的。然后你就可以将你的 `IEnumerable<Giraffe>` 和 `IEnumerable<Animal>` 传递给该函数，一切都会正常。当然，我刚刚泄露了惊喜；这正是这个系列文章将要讨论的内容。
